## Investigation brief

The service desk has reported intermittent name-resolution failures from a teaching lab. Most requests follow the expected path, but one exchange takes a different route and arrives with a lower time-to-live value.

> **Research note:** treat the capture as evidence. Record what changed before deciding why it changed.

Your task is to identify the unusual exchange, name the application protocol, and submit a compact finding in flag form.

## Reading packet captures

Start with fields that remain comparable across requests:

1. Source and destination address
2. Transport protocol and destination port
3. Query name and response code
4. Time-to-live difference from the baseline

The relevant summary has already been extracted from the larger capture:

```text
packet 12  10.20.4.18 -> 10.20.0.53  UDP/53  TTL 64  query lab.example
packet 18  10.20.4.18 -> 10.20.0.91  UDP/53  TTL 47  query lab.example
packet 19  10.20.0.91 -> 10.20.4.18  UDP/53  TTL 47  response NOERROR
```

The baseline TTL is `64`. Preserve the difference as a positive integer for the final flag.
